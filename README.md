# YDI-Shared

YDIの複数リポジトリから再利用する、**公開可能な共通部品**を置くリポジトリ。

## 役割

YDI-Sharedは、public / privateを問わず複数のYDIリポジトリから共通利用したい部品を管理する。

対象例:

- 再利用可能なGitHub Actions workflow
- 共通Action
- 小さな検査スクリプト
- 公開して問題ない共通ルールや設定断片

最初の用途は、YDI各リポジトリで使う構造チェック。

## 境界

ここには、**公開して問題ないものだけ**置く。

置かないもの:

- 秘密情報
- 個人情報
- YDI内部の現在状態
- BOD課題
- ユニットのLive / Instruction / エスカレ
- サービス固有の実装やデータ
- 非公開であること自体が安全性に関わる情報

共通部品から秘密情報が必要な場合でも、このリポジトリへ保存しない。
必要な値は利用側リポジトリから安全な方法で渡す。

## YDI内での位置づけ

YDI-Sharedはユニットではない。

- ULを持たない
- `Instruction.md` を持たない
- BOD課題を持たない
- 独自の仕事を自律的に開始しない

BODが必要な共通部品を定義し、各リポジトリから利用するための共有基盤として扱う。

## 配置方針

必要になったものだけ追加する。

想定する配置:

```text
.github/workflows/   再利用可能workflow
actions/             共通Action
scripts/             小さな共通処理
rules/               公開可能な共通ルール
```

ディレクトリは用途が発生するまで作らない。

## 分離基準

ある共通部品が、

- 独立したライフサイクルを持つ
- 単独で利用・公開される
- YDI-Sharedとは別にversioningやrelease管理が必要になる

状態になった場合は、専用リポジトリへの分離を検討する。

> 共通化のためにリポジトリを増やさない。独立した責任が生まれたときだけ分ける。
